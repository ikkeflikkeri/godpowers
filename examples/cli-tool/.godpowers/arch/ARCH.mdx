# System Architecture

## Options Considered

| Shape | Score | Why rejected | Trap flag |
|-------|-------|--------------|-----------|
| Single static binary (baseline) | 8.4 | Chosen. Meets the zero-runtime-dependency and portability NFRs with one cross-compile command. | [HYPOTHESIS] Hidden cost: each release must build and verify separate macOS and Linux artifacts for amd64 and arm64. |
| Shell script wrapping grep and awk | 7.2 | Rejected. The portability NFR requires identical behavior on macOS and Linux, and BSD awk diverges from GNU awk on the parsing this needs. | |
| Language-server-style daemon with a thin client | 4.9 | Rejected. The zero-runtime-dependency NFR and V1 CLI scope do not permit a resident service with lifecycle, port, and stale-state failure modes. | [HYPOTHESIS] Hidden cost: the daemon looks faster on repeat runs, but CI containers start cold every time, so the cache never warms. |

Scores include trap demotion and use the NFR map below. Novelty is not a
scoring axis.

## System Context (C4 Level 1)

```
[CI Runner / Engineer Terminal]
              |
              v
         [cilog binary]
              |
              v
         [stdout + exit code]
```

Single-binary CLI. No external services. Reads stdin or file; writes formatted report to stdout.

## Container Diagram (C4 Level 2)

| Container | Single Responsibility | Technology |
|-----------|----------------------|------------|
| `cli` | Argument parsing, file/stdin reading | Go 1.23 (per ADR-001) |
| `parser` | Detect CI format, locate FAILED step | Go (regex + state machine) |
| `formatter` | Render focused report with context | Go (no external lib) |

## Critical Flows

```
Focused failure report (crosses the untrusted-input boundary, touches 3 containers)

1. cli        -> cli         parse argv, resolve source (file path or stdin)
2. cli        -> parser      stream lines in 64 KB reads
3. parser     -> parser      sniff the first 100 lines for a format marker
4. parser     -> parser      scan for the FAILED step, holding 40 lines of context
5. parser     -> formatter   emit the matched step and its context window
6. formatter  -> stdout      render the report
7. cli        -> caller      exit 1 on a located failure, 0 on none, 2 on unreadable input
```

| Flow | Crosses | Writes at | Fails visibly at |
|------|---------|-----------|------------------|
| Focused failure report | untrusted-input boundary | nowhere; the tool holds no state | 7 (exit code 2 and a message on stderr) |

[DECISION] Nothing in this flow writes, so a retry is always free and no step
needs an idempotency key.

## Architecture Decision Records

### ADR-001: Go for the implementation
- **Context**: PRD requires static binary, zero runtime deps, multi-platform.
- **Decision**: Go 1.23 with cross-compilation.
- **Rationale**: A Go static binary beats the shell-script shape because it behaves identically on BSD and GNU userlands, and it beats the daemon shape because it needs no resident process. The standard library covers regex and CLI parsing.
- **Flip point**: If we need WebAssembly distribution or per-platform performance optimization, reconsider Rust.
- **Consequences**: Smaller binaries than Rust+tokio; mature CI tooling; standard library covers needs.

### ADR-002: Auto-detection over explicit format flags
- **Context**: Three CI log formats (GitHub Actions, Jenkins, Drone) have distinct markers.
- **Decision**: Sniff the first 100 lines for format markers; fall back to "unknown" with generic FAIL pattern matching.
- **Rationale**: Auto-detection beats mandatory `--format` flags because the acceptance flow requires direct file and stdin use without format setup. An explicit override remains the flip point if detection accuracy falls.
- **Flip point**: When sniffing accuracy drops below 90%, expose a `--format` override.
- **Consequences**: Slightly more startup cost; better UX.

### ADR-003: Streaming parser, not full file load
- **Context**: PRD NFR requires processing 10MB logs in 500ms.
- **Decision**: Line-by-line scanning with bounded ring buffer for context lines.
- **Rationale**: Streaming beats full-file loading because it keeps memory bounded while meeting the 10MB latency NFR. Full-file loading is simpler but gives up that bound without improving the required output.
- **Flip point**: Never; streaming is strictly superior here.
- **Consequences**: Memory footprint independent of input size.

## NFR-to-Architecture Map

| PRD NFR | Architectural Choice | ADR Reference |
|---------|---------------------|---------------|
| Latency 10MB in 500ms | Streaming parser, no allocations in hot loop | ADR-003 |
| Portability multi-platform | Go cross-compilation matrix in CI | ADR-001 |
| Footprint <5MB | Go static binary with `-ldflags="-s -w"` | ADR-001 |
| Dependencies zero runtime | Go static linking; no shared libs | ADR-001 |

[DECISION] Every NFR from PRD has an architectural choice mapped above.

## Capacity Envelope

| Input | Today | At the PRD horizon | Source |
|-------|-------|--------------------|--------|
| Log size per invocation | 2 MB median | 10 MB | PRD NFR states the latency budget at 10 MB |
| Invocations per CI run | 1 | 1 | one report per failed job, by design |
| Context lines retained | 40 | 40 | ring buffer size, fixed at compile time |

Derived, per container:

| Container | Derived load | Headroom on the chosen shape |
|-----------|--------------|------------------------------|
| `parser` | 10 MB in 500 ms = 20 MB/s sustained scan | [HYPOTHESIS] a line scanner with no hot-loop allocation sustains 20 MB/s on the CI runner class; validate with a 10 MB benchmark before the first release |
| `formatter` | one report, bounded by the 40-line window | constant |
| memory | 64 KB read buffer plus 40 retained lines, about 128 KB | independent of input size (ADR-003) |

[DECISION] Saturates first: nothing at the PRD horizon. The binding constraint
is single-invocation latency, not throughput, so ADR-003's flip point is a
latency regression rather than a volume.

## Trust Boundaries

```
[stdin / argv]
    |
=== TRUST BOUNDARY: untrusted input; no eval, no shell exec ===
    |
[parser]
    |
[stdout]
```

The tool reads but never executes. Logs may contain malicious content; we
output them verbatim only after format-validating.

## Failure and Degradation

| Dependency | Timeout | On failure | Idempotent | User sees |
|------------|---------|------------|------------|-----------|
| stdin | 30s idle read | Abort, exit 2 | Yes; the tool holds no state | "no input received after 30s" on stderr |
| Input file | none; local read | Abort, exit 2, emit no partial report | Yes | the path and the OS error on stderr |
| Unrecognized log format | none | Fall back to generic FAIL matching | Yes | a "format not recognized, using generic matching" note above the report |

[DECISION] Backpressure: none to design. One input per invocation against a
fixed 64 KB buffer, so a larger log costs time and never memory.

[DECISION] Recovery: there is no persistent state to recover. Every invocation
starts clean, so rerunning the command is the recovery procedure.

For each container, what happens if it dies:

| Container | If it dies | Verdict |
|-----------|-----------|---------|
| `cli` | The invocation exits non-zero and prints nothing | SPOF by construction; accepted, because a single-process CLI has no partial-availability mode |
| `parser` | Same process, same exit | Not separable from `cli` |
| `formatter` | Same process, same exit | Not separable from `cli` |

[DECISION] A single static binary is one failure domain, and recording that is
the point: availability belongs to the CI job that invokes the tool, not to
this architecture.
